# Deploy ordo-standalone to vps-staidans — August 2026

Execution script for a Claude session (armature-infra runbook convention: run
step-by-step, **verify each step before the next**). Prepared 2026-08-07 in a
remote session where 1Password could not approve SSH/signing — everything local
is committed and ready; this finishes the job.

**Precondition:** running on a machine where 1Password can approve prompts
(Glen at the keyboard, not remoted in).

## 1 — Push the prepared commits

Both repos hold local unsigned commits (1Password signing was unavailable):

- `ordo-standalone` on `main`: the restructure + this runbook
- `armature-infra` on `main`: `a5834de` (ordo Caddyfile block)

```sh
# optional — re-sign the unsigned commits first (rewrites local history only):
#   git rebase origin/main --exec 'git commit --amend --no-edit -S'
git -C ~/armature-workbench/ordo-standalone push
git -C ~/armature-workbench/armature-infra push
```

Verify: `git -C ~/armature-workbench/ordo-standalone status` shows "up to date
with origin/main", clean tree.

## 2 — Clone onto the VPS

```sh
ssh vps-staidans
sudo mkdir -p /opt/ordo-standalone && sudo chown debian:debian /opt/ordo-standalone
git clone https://github.com/Inmused-Dev/ordo-standalone.git /opt/ordo-standalone
```

Verify: `ls /opt/ordo-standalone/site` → `index.html  liturgies  liturgies.json`.

## 3 — Bring up the container

```sh
cd /opt/ordo-standalone && docker compose up -d   # sudo if debian lacks docker group
```

Verify: `docker ps --filter name=ordo-standalone` shows Up, and
`docker exec ordo-standalone ls /usr/share/nginx/html` lists the three site entries.

## 4 — Add the Caddy route (reconcile live file first)

Locate the live Caddyfile:

```sh
docker inspect armature-caddy --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{println}}{{end}}'
```

**Precedent warning:** the live Caddyfile has diverged from the repo before.
In the directory that holds it, run `git status` / `git diff` first:

- Clean and tracking the repo → `git pull` (brings armature-infra `a5834de`).
- Diverged → keep the divergent bits, hand-add the `ordo.staidans.org.au`
  block from `armature-infra/provision/Caddyfile`, and reconcile repo↔live
  afterwards.

Then validate and reload:

```sh
docker exec armature-caddy caddy validate --config /etc/caddy/Caddyfile
docker exec armature-caddy caddy reload --config /etc/caddy/Caddyfile
```

## 5 — Verify at the origin (before DNS)

Still on the VPS:

```sh
curl -s -H "Host: ordo.staidans.org.au" http://127.0.0.1/ | grep -o "<title>[^<]*"
# → <title>Liturgies — St Aidan's
curl -s -o /dev/null -w "%{http_code} %{size_download}\n" \
  -H "Host: ordo.staidans.org.au" http://127.0.0.1/liturgies/2026-08-02-holy-communion.html
# → 200, ~5.3 MB
```

(Caddy's Let's Encrypt issuance for the new hostname fails until DNS points
here — expected; it retries automatically after the swap.)

## 6 — Swap DNS in Cloudflare (manual, Glen)

Zone `staidans.org.au` → DNS → record `ordo`:

- Currently points at render.com. Change it to an **A record with the same
  origin IP as the `auth` record**, Proxied (orange cloud) **on**.

## 7 — Verify publicly

From any device: <https://ordo.staidans.org.au> — index loads, both liturgies
open, previous/next buttons and page indication work on a tablet. Allow a
minute or two for Caddy's certificate issuance on first hit.

## 8 — Decommission render.com

In the render dashboard, suspend/delete the old static site once the new one
is confirmed serving.

## Rollback

Point the Cloudflare `ordo` record back at the render.com target — the render
site keeps working until step 8.
